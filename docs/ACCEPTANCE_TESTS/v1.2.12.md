## J. Release gates

Mandatory commands:

```bash
npm ci --include=optional
npm run check
node scripts/hygiene-check.mjs --all --strict
npm run verify:publish
```

Additional gates:

- GitHub `Check` and `Hygiene` pass on the final implementation commit
- Root/client/server/UI/startup/health/docs versions synchronized to v1.2.12
- `git diff --check` passes
- Only `.gitkeep` files tracked under runtime data directories
- No `dist`, `*.tsbuildinfo`, logs, generated workflows/monitor lists, credentials, or captures tracked
- Acceptance evidence lists every `NOT RUN` item honestly
- Current state, architecture, known issues, roadmap, changelog, and release checklist are current
- **No release tag or ZIP until all mandatory gates and owner approval are complete**

## Evidence rule

Each row must record commit SHA, command/fixture/environment, sanitized configuration, timestamps
and duration where applicable, expected and actual result, `PASS` / `FAIL` / `NOT RUN`, and a
screenshot/log/frame capture where appropriate. A `NOT RUN` row never becomes `PASS` because an
adjacent unit test passed.

## Explicit non-claims

Passing the UI screenshot matrix does not prove runtime or write safety. Passing unit tests does not
prove hardware or slow-consumer behavior. Hardware and extended-soak rows remain `NOT RUN` unless the
approved environment and evidence exist.
