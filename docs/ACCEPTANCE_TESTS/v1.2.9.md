# Draft Acceptance Test v1.2.9

Status: draft, not yet approved for implementation.

## Monitor scheduler

- Continuous monitor cycles must never overlap for the same list.
- The next delay begins only after the current cycle completes.
- START is idempotent and cannot create duplicate loops.
- STOP prevents the next item/cycle and invalidates stale generations.
- Device disconnect stops affected monitor loops without disconnecting unrelated devices.
- Monitor list configuration persists; runtime values and running state do not restore after restart.

## WebSocket server

- High-frequency traffic diagnostics are batched or throttled.
- Critical workflow, runtime, device, and monitor state events are not silently discarded.
- Broadcast inspects client readiness and buffered data.
- A slow or closed client does not destabilize other clients.

## WebSocket client

- Abnormal close triggers bounded reconnect backoff.
- Normal component cleanup does not trigger reconnect.
- Connection state displays LIVE, RECONNECTING, or OFFLINE.
- Successful reconnect resynchronizes workflows, active runtime, device state, monitor lists, monitoring state, validation, and recent traffic as approved.
- Reconnect must not reload the page, reset React Flow, or discard unsaved changes.

## Regression

- v1.2.8 protected behavior remains functional.
- `npm run check` passes.
