## Defect and model

Previously, window focus called refreshCatalog, immediately marking metadata unavailable.
Bindings became DRAFT, selection emptied, the healthy Runtime was disposed, and unchanged
metadata re-enabled a new Snapshot/socket lifecycle. The fix separates:

| State | Effective Catalog | Runtime |
|---|---|---|
| Initial / initial request pending | unavailable | disabled |
| Initial failure or malformed response | unavailable + accessible notice | disabled |
| First valid response | confirmed | eligible active View may start |
| Background pending | last confirmed | existing healthy session retained |
| Background failure/malformed response | last confirmed + non-blocking warning | retained |
| Background success | new confirmed metadata, warning cleared | semantic reconciliation |

Pending requests coalesce; only explicit/focus/active-entry refreshes are initiated. There
is no Catalog retry timer. Cleanup invalidates old request tokens, including late failures.
Successful responses are validated as metadata and copied before becoming confirmed state.
Equivalent reordered records reuse confirmed references; partial/failed responses are not committed.

The Provider uses a LOCAL semantic session key: canonical eligible SHARED_TAG selection,
confirmed binding status, type, enabled state, compatible capability and Number unit.
A changed Number unit fences old presentation before applying data under the new metadata.
No wire selectionKey/cursor change. Definition names/descriptions, unrelated definitions,
Workflow list labels, object allocation/order and Catalog pending/error state are not session
inputs. They can update metadata presentation without transport churn. Geometry and Page
formatting are not included. Binding resolver/matrix and persisted Element schema unchanged.

Provider change is required to reconcile relevant metadata when the wire identity set stays
unchanged. Its original browser lifecycle effect body is extracted for deterministic integration
testing; adapter/B2 recovery/disposal code is unchanged. Hidden/offline still pauses; visible/
online can request a fresh Snapshot. Focus alone adds no lifecycle. Edit/inactive remain
unsubscribed, saved Page navigation fences before async completion, and StrictMode scheduled
starts remain generation guarded. Unsubscribe is best effort followed by immediate disposal;
acknowledgment receipt is not guaranteed, and physical closing overlap requires browser evidence.

Warning is persistent `role="status"`, `aria-live="polite"`, `aria-atomic="true"`, with explicit
text about last-confirmed metadata and manual refresh. It does not replace Runtime transport,
quality or historical-value presentation. It clears only after successful refresh.
